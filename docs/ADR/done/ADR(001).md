# ADR 001: Use WebMCP as Primary Agent Interface Protocol

## Status

Accepted

## Context

AmbiOS AI needs a standardized way for AI agents to interact with the platform alongside human users. Multiple approaches exist: custom API-only agents, browser automation, chat-based interfaces, or standardized web agent protocols.

The WebMCP Challenge hackathon provides timing, community, and technical alignment for building an agent-native web platform.

## Decision

Adopt WebMCP as the primary protocol for agent interaction with AmbiOS AI. All agent capabilities will be exposed through WebMCP tools registered in the browser via `navigator.modelContext`.

## Consequences

**Positive:**
- Agents use structured, typed tools instead of fragile DOM automation
- Human and agent interfaces share the same backend logic
- Hackathon alignment provides community and visibility
- Future-proof as WebMCP becomes a web standard

**Negative:**
- Dependency on WebMCP browser support and adoption
- Limited to WebMCP-capable environments initially
- Need to maintain compatibility as WebMCP evolves

**Neutral:**
- Requires WebMCP testing in multiple browser environments
- Documentation must cover WebMCP-specific patterns

## Completion evidence

The canonical browser registry is implemented in `webmcp/register.ts`, mounted by
the Next.js client layout, and exposes the `ambios.*` tool namespace. The
verification log records the deployed Vercel/Worker topology, the registered
tool contract, and automated WebMCP evaluations. Native browser execution is
still correctly limited to compatible WebMCP runtimes; this ADR does not claim
universal browser support or provider-side execution for unverified vendors.
