# ADR 002: Cloudflare Workers Backend Runtime

> **Superseded for current delivery (2026-09-03).** ADR-021 is the active platform strategy: `apps/web` is the sole Next.js frontend on Vercel; Cloudflare hosts only the Hono Core and Connector/Execution Workers. This record remains historical decision context and is not a deployment instruction.

## Status

Accepted

## Context

AmbiOS AI requires a runtime that supports edge compute, low-latency API access, integrated storage primitives, and cost-effective scaling. Multiple options exist: traditional Node.js hosts, serverless platforms, container orchestration, or edge runtimes.

## Decision

Use Cloudflare Workers for the backend API, WebMCP gateway, provider execution, and webhooks. The Next.js frontend is hosted on Vercel. Leverage Cloudflare's integrated primitives: D1, KV, R2, Queues, Durable Objects, Cron Triggers, and Analytics Engine.

## Consequences

**Positive:**
- Tight integration with D1, KV, R2, Queues for operational data
- Edge compute reduces latency for global users
- Cost-effective for MVP and early growth
- Built-in security and DDoS protection

**Negative:**
- Workers runtime differs from Node.js (requires adaptation)
- Some NPM packages incompatible with Workers
- Learning curve for Cloudflare-specific patterns

**Neutral:**
- Requires Wrangler configuration and local development setup
- Need to manage multiple Cloudflare resources
