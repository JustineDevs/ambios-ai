# ADR 003: Dual-Database Strategy with D1 and Supabase

## Status

Accepted

## Context

AmbiOS AI needs to store operational data (tools, actions, incidents, budgets) and user-ai/auth data. A single database approach may not optimize for both operational performance and auth integration.

## Decision

Use a dual-database strategy:
- **D1** for core operational data: organizations, agents, tools, actions, incidents, docs, budgets, spend_log, integrations, sync_jobs
- **Supabase Postgres** for user profiles, auth metadata, and complex relational queries

## Consequences

**Positive:**
- D1 provides low-latency access from Workers for operational data
- Supabase Auth integration is seamless with Supabase Postgres
- Separation of concerns between operational and auth data
- Flexibility to optimize each database independently

**Negative:**
- Increased complexity in data synchronization
- Two databases to manage and monitor
- Potential for data inconsistency if not carefully managed

**Neutral:**
- Requires clear ownership definitions for each entity
- Need to document which data lives where
