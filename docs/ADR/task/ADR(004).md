# ADR 004: Supabase Auth with Google OAuth as Primary Identity Provider

## Status

Accepted

## Context

AmbiOS AI needs a secure, user-friendly authentication system. Building custom auth is risky and time-consuming. Multiple auth providers exist: Auth0, Clerk, NextAuth, Supabase Auth, or custom implementation.

## Decision

Use Supabase Auth with Google OAuth 2.0 as the primary authentication mechanism. Store user sessions and JWTs validated by Workers.

## Consequences

**Positive:**
- Fast setup with Google OAuth users expect
- Supabase provides session management and JWT validation
- Integrated with Supabase Postgres for user metadata
- Reduces security risk of building custom auth

**Negative:**
- Dependency on Supabase availability and pricing
- Google OAuth may not suit all enterprise customers initially
- Limited to Supabase Auth features unless extended

**Neutral:**
- Requires Supabase configuration and environment variables
- Need to handle JWT validation in Workers
