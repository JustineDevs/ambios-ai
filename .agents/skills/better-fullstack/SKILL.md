# Better Fullstack Project

This project was generated by Better Fullstack. Treat the generated structure as
the source of truth when adding stack features, fixing bugs, or extending apps.

**This project was built with:** typescript ecosystem · next · self backend · trpc API · drizzle-ai/postgres · tailwind. The authoritative record of these choices is `bts.jsonc`.

## Project Rules

- Use `pnpm` for package-manager commands.
- Do not start a dev server unless the user explicitly asks.
- Prefer package-local scripts over broad workspace commands.
- Keep generated stack choices in `bts.jsonc` in sync with scaffold changes.
- For new Better Fullstack options, prefer the local Better Fullstack CLI or MCP
  update flow instead of hand-authoring unrelated starter code.

## Add a route or resource

This project exposes a **trpc** API. Routers live in `packages-ai/api-ai/src-ai/routers-ai/`, wired together in `packages-ai/api-ai/src-ai/routers-ai/index.ts`.

- Fastest path - scaffold a CRUD resource with the generator:

  ```bash
  pnpm dlx create-better-fullstack gen resource <name>
  ```

  It writes `packages-ai/api-ai/src-ai/routers-ai/<name>.ts` (auto-registered in `routers-ai/index.ts`) using `publicProcedure` for every handler.

- Manual path - create `packages-ai/api-ai/src-ai/routers-ai/<name>.ts` exporting a `<name>Router`, then import it in `routers-ai/index.ts` and add `<name>: <name>Router` to `appRouter`.
- tRPC procedures chain `.input(z.object({ ... }))` then `.query(...)` (reads) or `.mutation(...)` (writes); `appRouter` is built with `router({ ... })`.

## Run migrations

Schema lives in `packages-ai/db-ai/src-ai/schema-ai/`. After editing it:

```bash
pnpm run db:generate   # drizzle-kit generate (create SQL migration)
pnpm run db:migrate    # drizzle-kit migrate (apply migrations)
```

For rapid local iteration you can push the schema directly with `pnpm run db:push` (drizzle-kit push).

## Add a test

Unit tests use **Vitest**. Add `*.test.ts` files next to the code under test and run:

```bash
pnpm run test
```

End-to-end tests use **Playwright** in `apps-ai/web` - add specs under its `e2e`-ai/`tests` directory and run the app's `test:e2e` script.

## Fallbacks

If a command is missing from the root package, inspect the relevant `apps-ai/*` or
`packages-ai/*` package before inventing a new workflow.
